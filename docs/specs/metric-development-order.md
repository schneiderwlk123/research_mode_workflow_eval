# Metric Development Order

具体指标严格按以下顺序逐个设计、确认、实现和验收。优先完成完整性、可靠性、参数、
语义和结果质量指标；时延、Token 消耗及成本等性能与资源指标统一放在最后阶段计算。

## 第一阶段：调用完整性与可靠性

1. 调用事件完整率
2. 完全重复调用率

## 第二阶段：参数、路由与规划

3. 必填参数完整率
4. Schema 合法率
5. 参数值准确率
6. 实体映射准确率
7. 路由 Precision
8. 路由 Recall
9. 漏调用率
10. 工具与 MCP 选择准确率
11. 子任务覆盖率
12. 子任务冗余率
13. 依赖关系正确率

## 第三阶段：需求、证据与忠实度

14. 意图识别准确率
15. 关键实体提取准确率
16. 时间范围提取准确率
17. 指标与口径提取准确率
18. 证据查准率
19. 证据查全率
20. 证据时效合格率
21. 证据可追溯率
22. 陈述支持率
23. 无依据陈述率
24. 数值忠实度（数值陈述支持率）

## 第四阶段：结果一致性与完成度

25. 中间结果与最终结果一致率
26. 公式计算准确率
27. 公式单元格覆盖率
28. 硬编码率
29. 循环引用率
30. 需求覆盖率
31. 严格任务完成率
32. 信息保留率
33. 信息坍缩率

## 第五阶段：时延、资源与成本

34. 单次工具调用时延
35. 工具调用时延 P50
36. 工具调用时延 P95
37. 工具调用时延 P99
38. 超时率
39. 研究模式端到端时延
40. 模型步骤时延
41. 研究模式 Token 消耗
42. 成本
43. 每个成功会话的平均成本

每一项进入编码前，都必须单独确认算法与数学公式、聊天/研究日志字段映射、异常边界及样例计算。无法由当前日志直接计算的指标必须返回“不可计算”及安全的缺失原因，不得估算。
