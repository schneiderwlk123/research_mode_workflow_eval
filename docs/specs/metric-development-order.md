# Metric Development Order

具体指标严格按以下顺序逐个设计、确认、实现和验收。优先完成完整性、可靠性、参数、
语义和结果质量指标；时延、Token 消耗及成本等性能与资源指标统一放在最后阶段计算。

## 第一阶段：调用完整性与可靠性

1. 调用事件完整率
2. 完全重复调用率

## 第二阶段：参数、路由与规划

3. 必填参数完整率
4. Schema 合法率
5. 参数值准确率
6. 路由 Precision
7. 路由 Recall
8. 漏调用率
9. 工具与 MCP 选择准确率
10. 子任务覆盖率
11. 子任务冗余率
12. 依赖关系正确率

## 第三阶段：需求、证据与忠实度

13. 意图识别准确率
14. 关键实体提取准确率
15. 时间范围提取准确率
16. 指标与口径提取准确率
17. 证据查准率
18. 证据查全率
19. 证据时效合格率
20. 证据可追溯率
21. 陈述支持率
22. 无依据陈述率
23. 数值忠实度（数值陈述支持率）

## 第四阶段：结果一致性与完成度

24. 中间结果与最终结果一致率
25. 公式计算准确率
26. 公式单元格覆盖率
27. 硬编码率
28. 循环引用率
29. 需求覆盖率
30. 严格任务完成率
31. 信息保留率

## 第五阶段：时延、资源与成本

33. 单次工具调用时延
34. 工具调用时延 P50
35. 工具调用时延 P95
36. 工具调用时延 P99
37. 超时率
38. 研究模式端到端时延
39. 模型步骤时延
40. 研究模式 Token 消耗
41. 成本
42. 每个成功会话的平均成本

每一项进入编码前，都必须单独确认算法与数学公式、聊天/研究日志字段映射、异常边界及样例计算。无法由当前日志直接计算的指标必须返回“不可计算”及安全的缺失原因，不得估算。
