# Metric Development Order

具体指标严格按以下顺序逐个设计、确认、实现和验收。优先完成完整性、可靠性、参数、
语义和结果质量指标；时延、Token 消耗及成本等性能与资源指标统一放在最后阶段计算。

## 第一阶段：调用完整性与可靠性

1. 调用事件完整率
2. 重试成功率
3. 重试率
4. 平均重试尝试次数
5. 无效重复调用率

## 第二阶段：参数、路由与规划

6. 必填参数完整率
7. Schema 合法率
8. 参数值准确率
9. 实体映射准确率
10. 路由 Precision
11. 路由 Recall
12. 漏调用率
13. 工具与 MCP 选择准确率
14. 子任务覆盖率
15. 子任务冗余率
16. 依赖关系正确率

## 第三阶段：需求、证据与忠实度

17. 意图识别准确率
18. 关键实体提取准确率
19. 时间范围提取准确率
20. 指标与口径提取准确率
21. 证据查准率
22. 证据查全率
23. 证据时效合格率
24. 证据可追溯率
25. 陈述支持率
26. 无依据陈述率
27. 数值忠实度（数值陈述支持率）

## 第四阶段：结果一致性与完成度

28. 中间结果与最终结果一致率
29. 公式计算准确率
30. 公式单元格覆盖率
31. 硬编码率
32. 循环引用率
33. 需求覆盖率
34. 严格任务完成率
35. 信息保留率
36. 信息坍缩率

## 第五阶段：时延、资源与成本

37. 单次工具调用时延
38. 工具调用时延 P50
39. 工具调用时延 P95
40. 工具调用时延 P99
41. 超时率
42. 研究模式端到端时延
43. 模型步骤时延
44. 研究模式 Token 消耗
45. 成本
46. 每个成功会话的平均成本

每一项进入编码前，都必须单独确认算法与数学公式、聊天/研究日志字段映射、异常边界及样例计算。无法由当前日志直接计算的指标必须返回“不可计算”及安全的缺失原因，不得估算。
