# Metric Development Order

具体指标严格按以下顺序逐个设计、确认、实现和验收。优先完成完整性、可靠性、参数、
语义和结果质量指标；时延与 Token 消耗等性能与资源指标统一放在最后阶段计算。

## 第一阶段：调用完整性与可靠性

1. 调用事件完整率
2. 完全重复调用率

## 第二阶段：参数、路由与规划

3. 必填参数完整率
4. Schema 合法率
5. 参数值准确率
6. 路由 Precision
7. 路由 Recall
8. 子任务冗余率

## 第三阶段：需求、证据与忠实度

9. 意图识别准确率
10. 时间范围提取准确率
11. 证据查准率
12. 陈述支持率

## 第四阶段：时延与资源

13. MCP 工具调用膨胀率
14. 超时率
15. 研究模式端到端时延
16. 模型步骤时延
17. 研究模式 Token 消耗
18. 研究模式上下文膨胀率

每一项进入编码前，都必须单独确认算法与数学公式、聊天/研究日志字段映射、异常边界及样例计算。
聊天模式和研究模式必须分别标记为“可直接计算”“有条件可计算”或“不可计算”；不可计算时
必须列出缺失字段或可靠映射、稳定原因码以及未来可恢复计算所需的 schema 变化。无法由当前
日志直接计算的指标必须返回“不可计算”及安全的缺失原因，不得估算或静默省略该模式。
