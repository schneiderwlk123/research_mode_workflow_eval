# Metric Development Order

具体指标严格按以下顺序逐个设计、确认、实现和验收。优先完成两类现有 Trace 可直接计算的确定性指标，再处理依赖 Golden Benchmark、Judge、交付物或价格表的指标。

## 第一阶段：调用完整性、可靠性与效率

1. 调用事件完整率
2. 调用成功率
3. 异常率
4. 单次工具调用时延
5. 工具调用时延 P50
6. 工具调用时延 P95
7. 工具调用时延 P99
8. 超时率
9. 重试成功率
10. 重试率
11. 平均重试尝试次数
12. 无效重复调用率
13. 研究模式端到端时延
14. 模型步骤时延
15. 研究模式 Token 消耗

## 第二阶段：参数、路由与规划

16. 必填参数完整率
17. Schema 合法率
18. 参数值准确率
19. 实体映射准确率
20. 路由 Precision
21. 路由 Recall
22. 漏调用率
23. 工具与 MCP 选择准确率
24. 子任务覆盖率
25. 子任务冗余率
26. 依赖关系正确率

## 第三阶段：需求、证据与忠实度

27. 意图识别准确率
28. 关键实体提取准确率
29. 时间范围提取准确率
30. 指标与口径提取准确率
31. 证据查准率
32. 证据查全率
33. 证据时效合格率
34. 证据可追溯率
35. 陈述支持率
36. 无依据陈述率
37. 数值忠实度（数值陈述支持率）

## 第四阶段：结果一致性、完成度与成本

38. 中间结果与最终结果一致率
39. 公式计算准确率
40. 公式单元格覆盖率
41. 硬编码率
42. 循环引用率
43. 需求覆盖率
44. 严格任务完成率
45. 信息保留率
46. 信息坍缩率
47. 成本
48. 每个成功会话的平均成本

每一项进入编码前，都必须单独确认算法与数学公式、聊天/研究日志字段映射、异常边界及样例计算。无法由当前日志直接计算的指标必须返回“不可计算”及安全的缺失原因，不得估算。
